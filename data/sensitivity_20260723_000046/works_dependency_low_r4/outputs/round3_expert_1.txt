A benchmark for judging whether a non-closure package is genuinely equivalent to a closure-led package is:

## 1) The package must match the **durable, not temporary**, cost gap
I would compare scenarios on a **steady-state annual savings basis** after implementation is complete, not on first-year cash relief alone.

A non-closure package is only “equivalent in substance” if it closes most of the gap that management says must be closed to restore target margins, typically assessed on:

- **permanent fixed-cost reduction**
- **structural capacity reduction**
- **unit-cost reduction at plant level**
- **EBIT / margin effect by 2030**
- **resilience to demand downside**

If the package relies heavily on one-off measures, accounting deferrals, or time-limited concessions, it is not equivalent.

## 2) Use a three-layer benchmark

### A. Financial equivalence
Compare each option on:

- **annual run-rate savings**
- **one-time restructuring cost**
- **payback period**
- **net present value**
- **margin uplift by 2028–2030**

A non-closure package should ideally deliver at least **70–90% of the run-rate savings** of the closure-led case if it is to be considered economically comparable under German co-determination constraints.  
If it delivers materially less, then it is not equivalent; it is a compromise with a weaker cost reset.

### B. Operational equivalence
Assess whether the package actually removes excess capacity, not just shifts it around.

Key questions:
- Does it reduce **installed capacity** or merely lower utilization?
- Does it remove **overlapping fixed overhead**?
- Does it simplify the plant network and logistics?
- Does it improve **line balance, productivity, and product allocation**?
- Does it reduce complexity enough to improve launch capability and quality?

A “no closure” package that leaves the same footprint but asks employees to work cheaper and harder is usually weaker than a closure package in structural terms.

### C. Execution equivalence
Under German co-determination, the real question is not only what is announced, but what can actually be executed.

Benchmark:
- **strike risk**
- **supervisory-board veto risk**
- **works-council implementation risk**
- **timing slippage**
- **supplier disruption**
- **reputational and political backlash**

A closure-led package may look stronger on paper, but if it cannot clear the governance barriers, its real execution value may be lower than a negotiated non-closure alternative.

## 3) What I would expect in the scenario table
For each package, I would want:

1. **Plants/sites affected**
2. **Capacity removed**
3. **Jobs reduced**
4. **Permanent annual savings**
5. **One-off costs**
6. **Timing of savings**
7. **Effect on German labor cost per vehicle**
8. **Impact on 2030 margin / return on sales**
9. **Industrial conflict risk**
10. **Board approval / veto risk**
11. **Strategic risk**: loss of capabilities, product launch capacity, or know-how

## 4) Practical benchmark for “equivalent in substance”
A non-closure package is close to equivalent if it combines:
- meaningful **capacity reduction**
- sizeable **labor-cost moderation**
- **voluntary exits**
- **redeployment / retraining**
- **overhead reduction**
- **product and volume reallocation**
- and some **management / owner contribution**

But it usually needs to be unusually strong to match closure economics. In automotive restructuring, closure or footprint reduction often produces the clearest permanent savings because it removes:
- fixed site overhead,
- underused assets,
- duplicated support functions,
- and future maintenance/energy burden.

So if the non-closure package cannot remove those elements in another way, it is likely inferior.

## 5) My bottom-line test
I would say a non-closure package is genuinely equivalent only if it satisfies all three:

- **It closes the structural cost gap in durable run-rate terms**
- **It materially reduces overcapacity**
- **It is executable under co-determination without relying on wishful implementation**

If it fails any one of those, it is not equivalent to a closure-led package; it is a softer restructuring with higher residual risk.
